# 六种模型的程序辅助对照

本轮使用真实模型，每个“模型 × 游戏 × 是否辅助”各一局，统一 seed `20260921`，单局最多 **500 个实际动作、500 次请求**。另设纯程序基线。测试使用 Dart 游戏引擎和本地模型代理，不是浏览器端到端测试。

正式结果：无辅助 12 组没有一组完成 500 步；有辅助 12 组中 11 组到 500 步仍存活，Qwen 0.8B 蛇局在第 2 次请求发生工具格式错误，只有 1 步执行成功。格式排障初测单独保留，不计作第二个正式种子或成功率样本。

下表每格为“有效步数 / 得分”；500 均表示预算到限且仍存活。

| 模型 | 方块无辅助 | 方块有辅助 | 蛇无辅助 | 蛇有辅助 |
| --- | --- | --- | --- | --- |
| Laya Multilingual 322M | 18 / 0（输入受阻） | 500 / 1200 | 1 / 0 | 500 / 210 |
| Qwen3.5 0.8B | 112 / 0 | 500 / 1000 | 7 / 0 | 1 / 0（协议中断） |
| Qwen3.5 4B | 112 / 0 | 500 / 1000 | 6 / 0 | 500 / 250 |
| Kev 4B | 112 / 0 | 500 / 1100 | 6 / 0 | 500 / 250 |
| DeepSeek Flash | 12 / 0 | 500 / 1000 | 9 / 0 | 500 / 250 |
| JEV 1.13.0 | 11 / 0 | 500 / 1000 | 43 / 10 | 500 / 250 |
| 纯程序，不调用模型 | — | 500 / 1000 | — | 500 / 250 |

方块辅助纠错：Laya 13/32 次模型请求、JEV 1/33，其余模型均为 0。蛇辅助纠错：Laya 1/500、Kev 10/500，其余已完成的 500 步组均为 0。模型在辅助提示下选择正确标签，与模型自行算出正确动作，是两件不同的事。

完整数值见 [结果表](results.md) 和 [结构化结果](results.json)，每组目录保存 `initial.json`、`trace.jsonl`、`summary.json`。模型版本见 [元数据](metadata.json)，输入、预算、接口和复现命令见 [实验方法](methodology.md)。

## 怎样解读辅助带来的提升

1. **程序规划改变了任务难度。** 无辅助方块需要模型从棋盘自行推导移动、旋转与落位；有辅助时，程序已经搜索合法路径、预测结果并指出最佳候选，模型主要是在这些选项中选择。执行器还负责整条路径。两者不是同一种独立规划任务。
2. **零纠错也可能高度依赖程序。** 提示中的 Best/Safe 等标签来自程序计算。没有改写动作，仅说明模型跟随了程序认可的候选，并不表示它自行完成了空间推理。蛇的路线和安全判断也已由循环算法完成。
3. **执行纠错是额外的保障。** trace 同时保留模型提议和最终动作；纠错次数能量化实际被替换的选择，但不能量化模型从候选标签中获得的帮助。蛇在不安全选择时还会按概率或程序规则挑选安全方向。
4. **纯程序基线用于检查模型的额外收益。** 同样的 500 步内，无模型的方块策略取得 1000 分，蛇取得 250 分。因此有辅助达到这些成绩，不能全部归为模型贡献。某些模型在程序评价相同的候选间选不同动作，会产生不同后续棋盘；单局分数更高也不等于证明了普遍的模型增益。
5. **辅助没有提高模型权重中的能力。** 本轮没有训练或学习，是给模型提供更多程序计算结果，并让执行器承担规划或纠错，提升的是整个系统的表现。

本轮是组合干预，无法将总增分准确拆成“规划贡献多少百分比、标签多少、纠错多少”。严格量化还需要固定输入和动作空间，再分别关闭标签、执行纠错及规划器的消融实验；本轮没有执行这些额外组，也没有多种子统计。

## 中断与初测记录

- `spawn_blocked`、`collision` 是游戏自然失败；`step_cap` 表示到 500 步时仍存活，是截尾观察，不是无限存活保证。
- `invalid_action` 是模型选择的方块输入被游戏规则拒绝，测试暂停，不能当作自然死亡或成功存活。
- `invalid_response` 是模型未按接口输出有效工具调用；`request_error` 是请求失败。它们不能作为有效对局得分排名。
- Qwen 的部分初测输出解释文字或普通方向字符串，而没有调用工具；格式检查失败即停止，没有从正文猜动作。首步失败的相关组追加了相同的工具输出格式要求后复测，观察和候选含义没有变化。0.8B 蛇还改用现有专用蛇接口，所有初测和通用工具复核记录在 [protocol-checks](protocol-checks/)。最终 0.8B 有辅助蛇仍在第 2 次请求返回非法工具格式，只有 1 步被执行；这不是策略碰撞。
- 为准备独立 Qwen worker，发现只启动 `backend.server:app` 不包含工具接口，会返回 404；改用已有的 `backend.tool_call:app`，并修正了复现文档。该启动检查没有成功调用模型，不计入游戏轮次。

## 范围与验证

JEV 页面仍默认无程序辅助，本轮有辅助 JEV 只是评测对照。Kev、DeepSeek、Qwen 4B 的蛇结果通过通用候选选择接口取得，不表示已加入贪吃蛇页面。

贪吃蛇两组使用相同的循环对齐出生状态及四个绝对方向。此前单独 JEV 测试使用默认出生状态和三个相对方向，不能直接并入本轮成绩。

`flutter analyze`、53 项 Flutter 测试和 `flutter build web` 已通过；业务引擎、模型后端及页面逻辑未修改，本次未重跑 Python 后端单测。逐帧核验命令：

```sh
dart run tool/verify_assistance.dart reports/assistance-comparison
```

模型服务有并行运行，HTTP 耗时仅作运行记录，不作严格速度排名。云端版本未来可能更新，不能保证重跑相同动作。单种子结果不足以估计成功率、显著性或长期稳定性。
