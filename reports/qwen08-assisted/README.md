## 五轮交流

按用户要求，先完成同一上下文的五轮问答，再开始本轮新对局。conversation.json 包含每轮原始输入、完整模型回复、token 和耗时。每次请求包含此前所有问答，不是五个无历史独立问题。反馈局面是明示的教学示例，不冒充实际游戏引擎执行结果。

1. 规则复述：能描述 down 与 hard_drop 的区别，但混淆锁定和失败。首轮我对“锁定后不能继续操作下一块”的表述省略了“同一个动作数组”限定，可能造成误导；第二轮已明确纠正，不能把首轮错误完全归因于模型。
2. 明确锁定正常、下一块可在新回合操作后，仍把 lines_cleared=1 推断为会立即失败，即使候选写明 game_over=false。
3. 反馈安全消一行得到100分、下一块正常出生的题设结果；模型选A却继续给出错误解释，还把消行数与结束标志混合判断。
4. 新标签 P/Q/R 测试：把 game_over=true 的 R 也判断为可继续，并选了安全但消0行的 P，未选安全消2行的 Q。
5. 再次纠正并换 K/M/N，终于选中安全消3行的 M；但 [right,rotate,hard_drop,left] 的实际执行序列错误回答为仅 hard_drop，漏掉前序动作。

这不是模型训练，权重未改变；多轮上下文也不能证明掌握规则。未把错误对话直接塞进生产提示。

## 提示词比较

根据对话写出 coached-prompt.txt，强调“所有候选都是锁定后的结果、锁定正常、game_over唯一决定立即结束、动作按顺序执行”。独立请求不携带教学历史，在来自第三个棋盘种子的6个局面比较：

| 版本 | 避免立即输且优先消行 | 全部数值优先级符合 |
|---|---:|---:|
| 原消行优先提示 | 6/6 | 1/6 |
| 交流后较长纠错版 | 5/6 | 2/6 |
| 后续精简纠错版 | 5/6 | 1/6 |

精简版是在看过这一组结果后继续探索，不能算独立保留集。所谓“全部优先级符合”指按明确字段次序筛选，不等于全局最优俄罗斯方块策略。长版虽有一项提升，却在更重要的安全/消行上退步，不能称为整体改善。

此前在两组各6个历史局面比较的英文短版、中文筛选版数据保留于 development.json、held_out.json。它们也没有提供稳定提升证据。

## hard_drop 动作

hard_drop 已加入游戏输入、合法动作信息、play_turn 的原生工具枚举和前端手动按钮。它保持当前列/旋转直接落下并锁定，只计一次动作。TurnExecutor 在锁定处停止，之前的 right/rotate 照常执行，之后的动作丢弃。辅助规划器把合法路径末尾连续 down 压缩成 hard_drop，保留中途旋转和横移。原 land_at_target 目标选择工具保留，二者含义不同。

21 项 Flutter 测试、23 项 Python 测试、本次相关 Dart 静态检查及 Web 构建通过。对照局使用新的动作规则，动作数不能直接与旧版未支持 hard_drop 的记录比较。
