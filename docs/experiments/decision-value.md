# 相同候选条件下的模型决策增益：decision-v1

## 当前进度与目标

实现、离线验证及首轮 60 局真实尝试已完成，47,221 个实际动作回放通过。其中 8 局请求失败，不能称为 60 局策略验证成功。报告见 `reports/local/decision-models-v1/README.md`。

按用户要求恢复服务后，8 个失败配置另存重试，1,749 个实际动作回放通过。Laya 两局取得有效结果；JEV 六局仍遇上游 HTTP 503/529，后续改为从原始失败点恢复，六个配置现已全部取得结果，8,336 个累计动作回放通过，恢复期间没有新增请求失败。恢复轨迹包含原始前缀，不能直接累加批次动作数。

最终综合报告见 `reports/local/decision-combined-v1/README.md`，包含策略成绩与原始中断/重试可靠性的分别统计。原始、重开、恢复三批记录均保留；恢复协议取消请求和总等待上限，不冒充原始无中断完成。旧 500/2000 步报告不混入本实验。上述 `reports/local/` 为本地证据，未发布到远程仓库。

问题是：在共同合法候选和执行器下，模型自主判断是否比现有启发式策略更好？这不是完全无程序辅助：合法候选枚举和路径执行仍是公共能力。暂不增加标签/纠错四组消融。

## 已固定的实验条件

- 三种策略：`random` 在合法候选中均匀随机选；`program` 使用现有启发式；`model` 只执行真实模型的原始选择。模型不接收最佳/安全标签、预测消行、空洞、高度等评价；不纠错、不重试、不补足失败局。
- 方块：每个策略每次选一个可达落点，使用同一个枚举器与路径执行器。提供完整棋盘、当前块、当前及下一块旋转形状和规则；候选仅给锁定原点列/行与旋转编号。未来会堵住出生区域的合法落点也保留。
- 蛇：所有组使用相同循环对齐的初始身体、食物和游戏 RNG；请求包含完整身体、食物、朝向与规则。只排除下一步会立即撞墙/撞身体的动作；未来会困死的方向保留。模型不接收循环路线、可达性、安全层结果，也不调用安全层改写动作。没有合法方向时记为 `no_legal_actions`（受困终止，不能算完成或持续存活），不强行调用空候选 API。
- 程序策略内部可以评价候选，但结果不出现在模型输入中。随机策略 RNG、游戏 RNG 和展示 RNG 分离。
- 每次独立打乱候选顺序和无意义编号；`order-seed` 控制展示置换。相同游戏种子、同一状态/决策序号和展示种子得到相同的映射。映射只存本地日志，不发送给模型。不要把不同展示置换当作额外独立游戏种子。
- 默认实际动作和请求各最多 2000；方块路径在动作上限严格截断。另有 3600 秒运行预算检查，进行中请求最多再等待 HTTP 超时。分别报告请求、完整落块数、动作、消行和终止原因；2000 动作不是相同落块数，也不是无限存活。
- Qwen 固定 `explicit-tool + required-tool`，仅约束格式及候选枚举，保留全部候选。后端必须返回 `constrained_decoding=true`，否则停止。JEV 使用云端 choice；Laya 使用 `native=true` 保留请求，输入过长应显式失败，不能截断或偷偷改写提示。

## 入口

```sh
# 不需要模型服务：三个位置参数分别是标签、游戏、策略
# 输出目录必须不存在。
dart run tool/benchmark_decision.dart program tetris program http://127.0.0.1:1 reports/local/decision-program-new seed=20260924 order-seed=0 max-steps=2000

# 真实 JEV：会调用云 API；先按 docs/reproduction.md 启动服务并配置环境变量中的密钥。
dart run tool/benchmark_decision.dart jev tetris model http://127.0.0.1:8770 reports/local/decision-jev-new seed=20260924 order-seed=0 max-steps=2000

# 离线核验该入口的新 schema；不能使用 verify_assistance.dart。
dart run tool/verify_decision.dart reports/local/decision-jev-new
```

`tool/run_decision_matrix.py` 默认验证种子 `20260924 20260925 20260926`，展示置换 `0 1`；随机、程序、JEV、Laya、Qwen 0.8B，两个游戏，共 60 局。这些新种子用于下一轮验证；`20260921` 只用于当前开发检查。预先固定输入和参数，不看验证结果再改提示并覆盖报告。

脚本不启动服务、不切换模型、不重试；读取健康状态，保存源码和哈希，逐局保存结果，并在结束后做回放核验。Qwen 默认端口 8776，应使用包含强制格式实现的独立服务，参见复现指南。JEV 8770、Laya 8769。运行期间不要修改源码；若检测到变化会报错。

```sh
# 先只跑无模型开发检查（示例输出目录请用新的名字）。
python3 tool/run_decision_matrix.py --root reports/local/decision-offline-new --models --seeds 20260921 --order-seeds 0 1

# 服务准备好后才执行完整真实实验。
python3 tool/run_decision_matrix.py --root reports/local/decision-models-new
```

完整默认矩阵可能产生最多 24000 次 JEV 请求；方块通常因一次选完整路径而远少于上限。先检查首个模型请求是否完整送达、真实模型/revision 是否正确和输入长度限制；不要把接口错误当成模型决策差。

## 记录与分析

每局记录 `initial.json`、`trace.jsonl`、`summary.json`；轨迹包含请求、原始响应、本地候选映射、原选/执行、实际路径、前后状态，以及请求失败现场。执行纠错次数必须为 0。模型组与基线按 `(game, seed, order_seed)` 配对，不拿不同局面逐帧决策作公平横比。

主要报告模型相对程序、随机基线的分差，分种子展示；再检查两种展示排列是否改变结论。报告达到上限的比例、受困/死亡/格式/连接错误。完整局成绩与系统失败分开解释，不能用中断前得分与 2000 步得分直接推断策略差异。请求数、输入输出 token 与延迟另列；异构后端 token 口径不同。三种子只提供探索性证据，不宣布统计显著性。

## 已验证（本分支会话）

- 7 项单测：完整状态与无评价泄漏、候选置换不改变集合/基线、劣质合法落点不纠正、未来危险但合法蛇方向保留、路径上限截断、未知选择不修改状态、受困时空候选。
- 两种展示置换 × 两个游戏 × 两种无模型策略，共 8 局离线实际运行；置换前后同策略轨迹一致。程序方块 2000 步/6100 分，蛇 2000 步/800 分；随机方块 238 步/0 分，随机蛇 446 步/30 分后无合法方向。证据：`reports/local/decision-v1-offline-check/`。
- 本地 HTTP 假模型仅验证请求和返回动作的执行链路、连接失败记录；不是模型成绩。证据：`reports/local/decision-v1-http-fixture/`。
- 已进行 decision-v1 真实推理，状态见文首；未进行浏览器端到端验证。本协议实现未改页面、游戏规则或历史报告。

## 服务失败后的显式重试

首轮按固定设计不自动重试。用户随后明确要求恢复服务并重跑失败配置，使用独立目录记录，不覆盖首轮。恢复服务并完成真实请求检查后可执行：

```sh
python3 tool/retry_decision_failures.py reports/local/decision-models-v1 reports/local/decision-models-retry-new
```

该脚本核对原实验源码哈希，只为含错误的配置各运行一次完整新局，JEV/Laya 按模型分队列并行。它不会重启服务、改提示词或循环重试直到成功。云端上游持续拒绝请求时，应记录未完成范围，不能把重试前后数据拼接成一局。
